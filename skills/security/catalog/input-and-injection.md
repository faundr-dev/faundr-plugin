# User input and injection
When to read: whenever there is server code that builds queries, commands, file paths, templates or HTML with outside data; or a front end that renders HTML/markdown coming from a user, an external API or an LLM.

How to work: for each candidate, trace source → transformation → sink. Source = anything the user controls (body, query, params, headers, cookies, file name, file content, third-party webhook, LLM output, data already saved by another user). Sink = the dangerous point (query, exec, fs, render). The control that rules it out has to be on the path, before the sink, and be the right kind for that context (escaping HTML does not protect SQL; `path.join` is not a containment check).

## sqli-raw-e-concatenacao — SQL built with user text
- Typical severity: critical (read/change the whole database, login bypass). Goes down to medium if the only interpolated value is validated as a number/enum beforehand.
- Where to look: template strings in SQL. Grep: `` sql` `` with `${` outside safe helpers, `$queryRawUnsafe(`, `$executeRawUnsafe(`, `Prisma.raw(`, `sql.raw(` (Drizzle), `knex.raw(` with concatenation, `.whereRaw(`, `.orderByRaw(`, `sequelize.query(` with a template, `db.query('... ' + x)`, `pool.query(\`...${`, `env.DB.prepare(\`...${` (Cloudflare D1), `supabase.rpc` calling a function that uses `execute format(` with `%s`.
- How to confirm by reading the code: see whether the value goes in as a parameter (placeholder) or as text. Safe forms: `` prisma.$queryRaw`... ${x}` `` (tagged template parameterizes), `` sql`... ${x}` `` from Drizzle/`postgres`/`@vercel/postgres`, `db.query('... $1', [x])`, `env.DB.prepare('... ?').bind(x)`. Unsafe forms: `$queryRawUnsafe` with a template, `sql.raw(x)`, concatenation with `+`. Identifiers (column/table name in `ORDER BY`) cannot be parameterized: they need an allowlist.
- Ruled out if: the value is passed as a parameter; or it is an identifier validated against a fixed allowlist (`['created_at','name'].includes(sort)`); or it is converted to a number (`Number.parseInt` with a `NaN` check) beforehand.
- Does not rule out: "it uses an ORM" (the `*Raw`/`*Unsafe` methods do not protect); manual escaping with `replace("'", "''")`; Zod validation `z.string()` (accepts any text); in PL/pgSQL, `execute 'select ... ' || p_x` or `format('%s', p_x)` (use `%L`/`%I` or `using`).
- How to fix:
  ```ts
  const rows = await prisma.$queryRaw`SELECT * FROM "Post" WHERE title ILIKE ${'%' + q + '%'}`;
  const col = ({ name: 'name', date: 'created_at' } as const)[sort] ?? 'created_at';
  ```
- CWE: CWE-89

## nosqli-operadores — User object used as a filter (MongoDB and similar)
- Typical severity: critical on login (`{ password: { $ne: null } }` gets in without a password); high on data queries.
- Where to look: `User.findOne({ email: req.body.email, password: req.body.password })`, `collection.find(req.query)`, `find({ ...req.body })`, `$where`, `$expr` with user values; `mapReduce`. Also PostgREST filters built from user text (`.or(\`name.ilike.%${q}%\`)`), which allow injecting extra conditions into the filter string.
- How to confirm by reading the code: see whether the filter fields can arrive as an object instead of a string (a JSON body accepts `{"$ne": null}`; Express's `qs` converts `?password[$ne]=x` into an object).
- Ruled out if: a schema (Zod) requires `z.string()` on each field before the filter; or `mongoose` with `sanitizeFilter: true`/`mongo-sanitize`; or the filter is built field by field with `String(x)`. For Supabase's `.or()`: the user's value does not go into the filter string (use `.ilike('name', \`%${q}%\`)`, which parameterizes).
- Does not rule out: TypeScript saying `string` (it does not validate at runtime).
- How to fix: validate types with Zod before the query; never spread `req.query`/`req.body` into a filter.
- CWE: CWE-943

## command-injection — System command with user text
- Typical severity: critical (code execution on the server).
- Where to look: `child_process.exec(`, `execSync(`, `spawn(..., { shell: true })`, `` $`...` `` (zx/Bun shell with a built string), `new Function(`, `eval(`, `vm.runInNewContext(`; tools that call `ffmpeg`, `imagemagick`, `git`, `pdftk`, `yt-dlp` with a file name or URL from the user.
- How to confirm by reading the code: `exec` goes through a shell, so `;`, `|`, `$()` work. `execFile`/`spawn` without `shell` receive arguments in an array (safe against the shell), but still accept option injection if the value starts with `-` (e.g.: `git` with `--upload-pack=`).
- Ruled out if: `execFile`/`spawn` with an argument array, without `shell: true`, and the user's value comes after `--` or is validated by a strict regex (e.g.: `/^[a-zA-Z0-9_-]+$/`).
- Does not rule out: quotes around the value (`exec(\`convert "${file}"\`)`); removing only `;`.
- How to fix: `execFile('ffmpeg', ['-i', '--', inputPath, outPath])` with paths generated by the server; avoid `eval`/`new Function` with any external data.
- CWE: CWE-78

## ssti-template — Template built with user text
- Typical severity: critical (in EJS/Pug/Handlebars/Nunjucks it usually leads to code execution); medium in engines without code access.
- Where to look: `ejs.render(userString`, `pug.render(`, `Handlebars.compile(userInput)`, `nunjucks.renderString(`, `_.template(userInput)`; emails "customizable" by the user; templates saved in the database and editable by customers.
- How to confirm by reading the code: the problem is compiling the user's text as a template, not passing the value as a variable. `ejs.render(templateFixo, { name: userName })` is safe; `ejs.render(userTemplate, data)` is not.
- Ruled out if: templates fixed in the code and the user only supplies values; or a logic-less engine (Mustache "logic-less") with automatic escaping and no dangerous helpers.
- Does not rule out: "only admins edit the template" (reduces severity, does not rule it out).
- How to fix: do not compile user text; if customization is needed, use simple placeholders replaced with `replaceAll('{{name}}', escape(value))`.
- CWE: CWE-1336

## path-traversal — File path with a name from the user
- Typical severity: critical on writes (overwrites code/config); high on reads (`.env`, keys, source code).
- Where to look: `fs.readFile(`, `fs.createReadStream(`, `fs.writeFile(`, `res.sendFile(`, `res.download(`, `path.join(UPLOAD_DIR, req.params.name)`, zip extraction (`adm-zip`, `unzipper`, `tar`) without checking entries, S3/R2 keys built with the user's name.
- How to confirm by reading the code: `path.join('/uploads', '../../.env')` resolves outside. There must be resolution + a containment check.
- Ruled out if: `const p = path.resolve(BASE, name); if (!p.startsWith(BASE + path.sep)) throw ...`; or the name is generated by the server (UUID) and the original stays only in the database; or an allowlist of names. In `res.sendFile(name, { root: BASE })` Express blocks `..` in the relative path.
- Does not rule out: `name.replace('../', '')` (not recursive; `....//` gets through); a check before URL decoding; `path.join` alone.
- How to fix: generate names on the server; for reads, resolve and check containment; in zips, reject entries with `..` or an absolute path.
- CWE: CWE-22

## xss-dangerously-set-inner-html — User HTML rendered without sanitizing
- Typical severity: high for stored XSS (hits other users, steals the session if the token is in `localStorage`, acts on behalf of the victim); medium for reflected; low for self-XSS (only the user themselves sees what they typed).
- Where to look: React `dangerouslySetInnerHTML`, Vue `v-html`, Svelte `{@html`, Angular `[innerHTML]` with `bypassSecurityTrustHtml`, DOM `innerHTML =`, `outerHTML`, `insertAdjacentHTML`, `document.write`; markdown: `marked(`, `markdown-it` with `html: true`, `react-markdown` with `rehype-raw`, `showdown`; rich editors (TipTap/Quill) saving HTML that is later rendered raw.
- How to confirm by reading the code: trace the content back to its origin. If it is from the user, a third party or an LLM, it must go through allowlist sanitization before the sink (or at save time, as long as every write goes through it).
- Ruled out if: `DOMPurify.sanitize(html)`/`isomorphic-dompurify`/`sanitize-html` with the default or a stricter configuration on the path; `react-markdown` without `rehype-raw` (does not render raw HTML); 100% static content from the code.
- Does not rule out: sanitizing with a regex (`replace(/<script>/g, '')`); sanitizing in the front end before sending (the attacker calls the API directly); DOMPurify configured with `ADD_TAGS: ['iframe']`/`ADD_ATTR: ['onerror']`; sanitizing and then modifying the string.
- How to fix: `<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(post.html) }} />`, or render as text.
- CWE: CWE-79

## xss-href-javascript — User URL in href/src
- Typical severity: medium to high (a click runs script on the app's domain).
- Where to look: `<a href={user.website}>`, `<iframe src={...}>`, `window.location = param`, `window.open(param)`, `<object data>`; links in profiles, bios, "company website".
- How to confirm by reading the code: React does not block `javascript:` in `href` (it only warns in the console in recent versions). See whether the URL is validated by protocol.
- Ruled out if: `new URL(u).protocol` checked against `['http:', 'https:']` when saving or rendering.
- Does not rule out: `includes('http')` (accepts `javascript:alert(1)//http`); validation only in the front-end form; blocking only the lowercase string `javascript:` (`JavaScript:` and spaces/tabs before it also work).
- How to fix: `const safe = ['http:', 'https:'].includes(new URL(u).protocol) ? u : '#'` (with try/catch for an invalid URL).
- CWE: CWE-79

## prototype-pollution — Recursive merge with user keys
- Typical severity: medium; high if the polluted object affects authorization (`if (user.isAdmin)` inherited from the prototype) or leads to execution via a gadget.
- Where to look: custom deep merge functions (`function deepMerge(target, src)` with `for (const key in src)`), `lodash.merge`/`_.defaultsDeep`/`_.set` with a path from the user, recursive `Object.assign`, query parsers that accept `__proto__`; "user-saved" settings merged with defaults.
- How to confirm by reading the code: see whether the keys `__proto__`, `constructor`, `prototype` are filtered before assignment and whether the source is user JSON.
- Ruled out if: the merge ignores those keys, or uses `Object.create(null)`/`Map`, or the input goes through a strict schema (Zod `z.object` strips unknown keys) before the merge; updated `lodash` (fixed versions block `__proto__` in `merge`/`set`).
- Does not rule out: "`JSON.parse` is safe" (it creates the `__proto__` key as an own property; it is the merge that pollutes).
- How to fix: validate with a schema beforehand; in the merge, `if (key === '__proto__' || key === 'constructor' || key === 'prototype') continue;`.
- CWE: CWE-1321

## deserializacao-insegura — Deserializing user data with a format that executes code
- Typical severity: critical.
- Where to look: `node-serialize` (`unserialize`), `serialize-javascript` used in reverse with `eval`, `js-yaml` `load` in old versions (<4) or with a schema that allows functions, `vm`/`eval` over JSON; in Python, `pickle.loads`, `yaml.load` without `SafeLoader`; cookies/sessions serialized without a signature.
- How to confirm by reading the code: identify the origin of the deserialized bytes; if they come from the user, the format must be data-only (JSON).
- Ruled out if: `JSON.parse` + schema validation; `js-yaml` ≥4's `yaml.load` (safe by default); data signed by the server (HMAC verified beforehand).
- Does not rule out: "the cookie is base64" (that is not a signature).
- How to fix: switch to JSON + Zod; sign whatever needs to come back from the client.
- CWE: CWE-502

## open-redirect — Redirect to a URL from a parameter
- Typical severity: low on its own (phishing); medium/high if it chains with OAuth (leaks `code`/token) or SSRF.
- Where to look: `redirect(searchParams.get('next'))`, `NextResponse.redirect(new URL(param))`, `res.redirect(req.query.url)`, `window.location.href = params.get('returnTo')`, routes `/go?url=`, `/out?to=`. Specific case of the login callback in `authentication.md` (`oauth-redirect-e-next`).
- How to confirm by reading the code: see whether the destination is restricted to a safe relative path or an allowlist of origins.
- Ruled out if: `raw.startsWith('/') && !raw.startsWith('//') && !raw.includes('\\')`; or `new URL(raw, base).origin === base` with an allowlist.
- Does not rule out: `url.includes('meusite.com')` (accepts `meusite.com.evil.io`); `startsWith('https://meusite.com')` (accepts `https://meusite.com.evil.io`).
- How to fix: accept only relative paths or destination IDs mapped on the server.
- CWE: CWE-601
